# 写真に言葉がついていなくても、探せます

整理されていない大量の写真から、目当ての1枚を見つけ出す仕組みについてのご説明です。技術的な知識は前提にしていませんので、そのままお読みいただけます。

---

## 1. まずは、猫と犬のデモから

手元に、猫と犬の写真が60枚あるとします。ファイル名は `IMG_2847.jpg` のような、中身が分からないものばかり。タグもキャプションも、何もついていません。

この60枚をそのまま仕組みに読み込ませて、「猫」と「犬」という2つの言葉だけを渡しました。結果は、**60枚すべてが正しく仕分けられました**。猫30枚、犬30枚、間違いはゼロです。

事前に1枚も人の手で分類していません。「これは猫」と教えたわけでもありません。写真を読み込んで、言葉を2つ渡しただけです。

さらに、検索欄に「cat」と打ち込むと、上位に並ぶのはすべて猫の写真でした。猫の写真を1枚選んで「これに似た写真」と指定すれば、他の猫の写真が並びます。

繰り返しますが、**写真には最初から最後まで、何の言葉もついていません**。

なぜこんなことができるのか、というのがこの資料の本題です。

## 2. 仕組み — AIは写真を「意味の地図」の上に置いています

### 写真を「場所」に変換する

この仕組みの中心にあるのは、**写真を見て、それが意味的にどのあたりのものかを判断し、地図の上の一点として記録する**AIです。

広い地図を想像してください。この地図には住所ではなく「意味」が並んでいます。猫の写真は地図のある一角に置かれ、犬の写真は少し離れた別の一角に置かれます。同じ猫の写真同士は、ごく近くに固まります。トラックの写真は、猫からも犬からもずっと遠い場所に置かれます。

AIは写真を1枚ずつ見て、「この写真はこの地図のここです」と場所を決めていきます。この「場所」を表す数字の並びのことを、専門的には**ベクトル**と呼びます。難しく考える必要はありません。**写真の意味を、地図上の座標に置き換えたもの**、と捉えていただければ十分です。

写真1枚が、768個の数字の組み合わせで表される座標になります。数字が多いのは、「猫か犬か」だけでなく、色、形、質感、背景、雰囲気といった無数の要素を同時に表現するためです。

### 言葉も、同じ地図の上に置かれます

ここが一番の勘所です。

このAIは、写真だけでなく**言葉も同じ地図の上に置けます**。「猫の写真」という文章を渡すと、AIはその言葉を地図上の一点に置きます。そしてその点は、実際の猫の写真が集まっている場所の、すぐ近くに落ちます。

写真と言葉が同じ地図を共有している。だから、こうなります。

> 「猫の写真」と入力する → その言葉が地図上に置かれる → その場所の近くにある写真を集めてくる → 猫の写真が出てくる

**写真に「猫」というタグがついている必要は、まったくありません。** タグを探しているのではなく、地図上の距離を測っているからです。

同じ理屈で、「この写真に似た写真」も探せます。手元の写真の座標を調べて、その近くにあるものを集めるだけです。

### 検索が「言い換え」に強い理由

この方式には、うれしい副作用があります。地図上の距離で探しているので、**言葉が完全に一致していなくても構いません**。

「ふわふわした毛の動物」と入力しても、その言葉の座標は猫の写真の近くに落ちます。「猫」という単語をどこにも使っていないのに、猫の写真が出てくる。従来のタグ検索やファイル名検索では、タグに登録された言葉と違う言い回しをした瞬間に、何も出てこなくなっていました。その壁がありません。

## 3. 「写真に言葉がない」問題への、3つの答え

「AIで写真を探す」という話は一括りにされがちですが、実際には**性格の違う3つの手段**があります。できることも、費用も、注意点も、それぞれ違います。ここを混ぜて考えると期待がずれてしまうので、分けてご説明します。

|                  | 何をするか             | 人の手間         | 費用                | 写真が外部に出るか |
| ---------------- | ---------------------- | ---------------- | ------------------- | ------------------ |
| ① 言葉なしで探す | 言葉をつけずに探す     | ゼロ             | 無料                | 出ない             |
| ② 言葉を増やす   | 人が決めた言葉を広げる | 少し（確認作業） | 無料                | 出ない             |
| ③ 言葉を作らせる | AIに言葉を書かせる     | ほぼゼロ         | 1枚あたり0.3〜0.6円 | **出る**           |

### ① 言葉なしで探す

先ほどご説明したそのままです。写真に何も付けないまま、2通りの探し方ができます。

- **文章で探す** — 「青い6ピンのコネクタ」のように、探しているものを言葉で書くと、それらしい写真が並びます。
- **写真で探す** — 手元の1枚を指定すると、それに似た写真が並びます。品番も名前も分からないけれど「これと同じやつ」を探したい、という場面で効きます。

準備は、写真をひととおり読み込ませるだけ。**人が写真に言葉をつける作業は一切発生しません。** 「写真が見つからない」という困りごとの、かなりの部分はこれだけで解決します。

### ② 言葉を増やす — 人が決めた言葉を、システムが広げる

とはいえ、一覧画面に整理された言葉が並んでいてほしい、という場面はあります。そこで2つ目です。

大事な前提として、**言葉を決めるのは人間です。AIが勝手に語彙を生み出すわけではありません。** システムがやるのは、人が渡した言葉を写真全体に広げることです。

**(a) 用意した言葉を、全体に当てはめる**

「コンデンサ」「抵抗」「コネクタ」のように、お客様の業務で実際に使われている言葉のリストを渡します。システムは全部の写真について、「この写真はどの言葉に近いか」を地図上の距離で測り、近いものを候補として提案します。

**(b) 1枚に付けた言葉が、似た写真に広がる**

こちらのほうが体感的な効果は大きいかもしれません。ある写真1枚に「不良品」と付けると、システムがその写真の近くにある写真を探し出し、**「これにも同じ言葉を付けますか？」と提案してきます**。

提案は1枚ずつ表示され、人が「はい」「いいえ」を選びます。実際のデータで試したところ、猫の写真1枚に言葉を付けたら、提案された5枚はすべて猫でした。

これで作業の性質が変わります。「1万枚に言葉を付ける」ではなく、「数枚に付けて、あとは提案に答えていく」になります。

**点数の読み方について、ひとつだけ**

この機能の画面には「0.06」「62%」といった数値が出ます。これは**確信度ではなく、地図上での近さ**です。0.06 は「6%の確からしさ」ではなく、「0.04 の写真よりは近い」という意味しか持ちません。

そのため、**どこから上を採用するかの線引き（しきい値）は、扱う写真と語彙に合わせて調整する前提**の項目です。最初は少し低めに設定して、提案された内容を見ながら詰めていく。この調整作業自体は、導入時に一度やれば済むものです。

**日本語について** — ①②で使っているAIは英語中心で学習されているため、日本語の検索語はいったん英語に置き換えてから渡す方式を想定しています。多言語対応のAIに差し替える案も検討しましたが、ライセンスや動作環境の制約があり、本PoCでは置き換え方式を推奨としました。なお③では、この制約自体がなくなります。

### ③ AIに言葉を作らせる — 別料金・写真は外部に送られます

①②は、**言葉を新しく生み出すことはしません**。①は言葉を使わずに探し、②は人が決めた言葉を広げるだけです。

3つ目だけが、本当の意味で「AIが言葉を作る」手段です。写真をAIに見せて、**説明文とタグをゼロから書かせます**。①②が「用意された言葉のどれに近いか」しか答えられないのに対し、こちらは写真を見て言葉そのものを書き起こします。

ただし、これは①②とは性質が違うため、必ず4点をご確認ください。

**1. 写真が社外に出ます**

この機能は、写真を外部のAIサービス（Anthropic社のClaude）に送信します。**①②が手元の機械の中だけで完結するのに対し、③だけは写真がインターネットを経由して外部に出ます。**

機密情報や、お客様の資産が写り込んだ写真を扱う場合は、この点の判断が先に必要です。仕組みの側では、**この機能だけは明示的な承認オプションを付けないと動かない**ようにしてあります。うっかり実行してしまうことはありません。

**2. 費用がかかります**

1枚あたりおよそ **0.3円〜0.6円** です。

- 1,000枚 → **300円〜600円ほど**
- 10,000枚 → **3,000円〜6,000円ほど**

まとめて処理する仕組み（バッチ処理）を使えば、これがおよそ半額になります。為替や各社の価格改定で変わりますので、実際にご検討いただく際は改めて見積もります。

一度処理して採用したタグはそのまま保存されますので、**同じ写真に毎回かかる費用ではありません**。ただし現状の試作版では、保存されるのは採用したタグだけで、AIが書いた説明文は画面に表示されるだけで残りません。説明文も蓄積したい場合は、保存先を用意する改修が必要です。

**3. 型番の読み取りには、追加の対応が必要です**

このAI自体は、部品に印刷された文字を読む力を持っています。ただし**現状の試作版では、送信しているのが一覧表示用の小さな画像（長辺256ピクセル）**のため、細かい印字までは読み取れません。

「黒い円筒形の部品」ではなく「電解コンデンサ」といったレベルの言葉は問題なく得られますが、「105℃ 470μF」のような小さな印字まで拾わせたい場合は、**元の解像度の写真を送る改修**が必要になります。技術的にはすぐ対応できる範囲ですが、その分アップロード量と費用は増えます。

**4. 日本語のタグが直接得られます**

翻訳を挟まず、最初から日本語でタグと説明文を書かせられます。②の日本語まわりの制約が、ここでは関係なくなります。

## 4. 正直にお伝えしておきたい限界

期待値を先に合わせておきたい部分です。

### 猫と犬は簡単で、部品の型番は難しい

先ほどの「猫と犬が100%」という結果は本物です。同時に、**あれは易しい問題でもあります**。猫と犬は見た目がはっきり違い、AIが学習した膨大な写真の中にいくらでも含まれていました。

一方、「このコンデンサとあのコンデンサ」のような区別は、まったく話が別です。見た目がほぼ同じで、違いは印刷された文字だけ。しかもその部品は、AIの学習材料にほとんど含まれていません。

こうした専門的な分野では、①②の精度は目に見えて落ちます。公開されている調査では、専門分野に絞った分類の正解率は平均で**36%程度**という数字も報告されています。

**まとめると、こうなります。**

| やりたいこと                             | ①②で足りるか                          |
| ---------------------------------------- | ------------------------------------- |
| 「部品」と「書類」と「現場写真」を分ける | 十分に可能です                        |
| 「コンデンサ」と「コネクタ」を分ける     | おおむね可能です                      |
| 「型番A」と「型番B」を分ける             | **難しく、③または追加学習が必要です** |

細かい型番レベルの識別が必要な場合は、③のAIタグ付けを元解像度で行うか、お客様の写真を数十枚〜数百枚使ってAIに追加学習をさせる、という手順が現実的です。いずれも本PoCの範囲外ですが、どちらも確立された手法です。

### 「探す」は今日から効き、「仕分ける」は調整が要ります

① の検索は、写真を読み込んだ時点で使えます。調整の余地がほとんどありません。

② の自動仕分けは、語彙の選び方としきい値の調整で結果が変わります。導入時にご一緒に詰めていく部分だとお考えください。

なお、②には**言葉を指定せずに「勝手にグループ分けさせる」機能**もあります。これは「この写真の山には何が入っているんだろう」を眺めるための探索用で、出てきたグループに名前は付きません。実データでは猫と犬をきれいに2グループに分けましたが、**必ず業務上意味のある分かれ方をする保証はありません**。仕分けの本命は、あくまで言葉を指定するほうです。

### 万能の「全自動整理」ではありません

この仕組みは、写真の山を全自動で完璧に整理する魔法ではありません。**探すことは今日からできます。仕分けは、人が少し関わることで実用的な精度になります。** そこは正直にお伝えしておきます。

## 5. 本番システムにするときは

今回お見せしているものは、**費用ゼロ・お客様の機械の中だけで完結する構成**で作られています。クラウド利用料もAPIキーも不要で、写真も外に出ません（③を除く）。検証をすばやく回すための、意図的な選択です。

本番システムでは、同じ流れのまま、部品だけをクラウドのサービスに置き換えられます。**作り直しではなく、差し替えです。**

| 工程             | 今回のPoC              | 本番構成                                    |
| ---------------- | ---------------------- | ------------------------------------------- |
| 写真を座標に変換 | 手元の機械で処理       | Google CloudのAIサービス（Vertex AI）で処理 |
| 座標の保管       | メモリ上の簡易保管     | 専用データベース（Qdrantなど）              |
| 写真の取り込み   | フォルダを指定して実行 | クラウドに写真がアップされた瞬間に自動処理  |
| 探す             | 全件を照合             | データベース側で高速に照合                  |

この構成は、[実際の事例記事](https://dev.classmethod.jp/articles/search-dance-movie-with-vertexai-and-qdrant/)で使われているものと同じ形です。今回のPoCは最初からその形を手元向けに置き換えて作ってありますので、戻す道筋がすでに通っています。

**どのくらいの規模まで今のままで足りるか**

今の方式は全件を毎回照合していますが、これが意外なほど速く、**2万枚でも1回の検索が0.02秒以下**です。**数万枚までは今の構成のまま**実用になります。

**10万枚を超えるあたり**から、専用データベースへの移行をご検討いただく段階です。枚数以外では、複数人が同時に使う、部署や日付で絞り込みながら検索する、写真が日々増え続ける、といった条件が移行の目安になります。

## まとめ

- **写真に言葉がついていなくても探せます。** AIが写真を「意味の地図」に配置し、言葉も同じ地図に置くためです。事前のタグ付けは要りません。
- **「言葉がない」問題への手段は3つあり、性格が違います。** ①言葉なしで探す（無料・手元完結）、②人が決めた言葉をシステムが広げる（無料・手元完結）、③AIに言葉を作らせる（有料・**写真が外部に出ます**）。
- **猫と犬の仕分けは100%でしたが、部品の型番レベルは①②だけでは困難です。** ③を元解像度で使うか、追加学習の領域になります。
- **費用は③のみ発生し、1,000枚で数百円程度**、しかも一度処理すれば繰り返しかかりません。
- **本番化は作り直しではなく差し替え**で、数万枚までは今の構成のままでも実用になります。

ご不明な点、お手元のデータで試してみたい点がありましたら、お気軽にお知らせください。実際の写真を使った検証も可能です。
